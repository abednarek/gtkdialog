pagesetupdialog

A top-level GTK+ 2 GtkPageSetupUnixDialog for selecting paper, orientation and margins with the native Unix printing interface.

Definition 

<pagesetupdialog tag_attr="value"...>
	<default>response</default>
	<variable>varname</variable>
	<input>response command</input>
	<input file>response filename</input>
	<sensitive>state</sensitive>
	<action signal="response">activity</action>...
	<output file>page setup filename</output>
	<output file print-settings="true">print settings filename</output>
</pagesetupdialog>

This element replaces the normal top-level window and cannot be nested or contain child widgets.

The page setup file is loaded first, after which explicit paper, orientation and margin attributes override its values. Standard writable GtkWindow properties such as title and modal are also accepted.

Value, Input and Signals

The variable contains the last dialog response. The built-in buttons normally produce apply or cancel; all common named responses and integer response IDs are accepted by default, input and value-setting actions. The variable is updated before actions connected to the default response signal run. A response does not implicitly close the dialog, so use exit for a root program or closewindow for a launched program.

Command and file input carry response text, not page geometry. The first refresh initializes input without emitting a response; later refreshes emit the input response and therefore run normal response actions. Input files use the common monitoring and automatic-refresh facilities.

Saving, Refreshing and Clearing

save serializes the current GtkPageSetup to every normal output file. An output directive with print-settings="true" instead serializes GtkPrintSettings; a default settings object receives an ignored gtkdialog placeholder key so even that key file can be loaded again. These files use GTK's portable key-file format and can be loaded with the corresponding tag attribute.

refresh reloads configured setup and print-settings files before reading response inputs. clear and removeselected restore default page and print settings and clear the stored response.

Availability, Lifecycle and Ownership

Configure with --with-unix-print to enable gtk+-unix-print-2.0 2.10 or later. A build without it still parses the tag and reports a precise diagnostic if the widget is used. The enabled optional feature appears as GTK2 Unix printing in gdlg2 --version.

The dialog keeps its own references or copies after page setup and print settings are assigned. Values returned by its getter functions remain borrowed from the dialog. Temporary objects created for loading, clearing and saving are therefore released exactly once. Closing the dialog releases its descriptions, inputs, file monitors and GTK-owned print objects through the normal top-level lifecycle. The source environment variable is preserved when a launched dialog uses the same name for its root variable, allowing a later relaunch.

Common Contract

Common directives, GtkWidget signals, state and general functions, and action conditions are documented in the common widget contract. The sections above describe facilities specific to this tag.

Example 

<pagesetupdialog title="Page setup" paper-name="iso_a4"
    orientation="portrait" top-margin="12" bottom-margin="12">
  <variable>PAGE_SETUP</variable>
  <output file>/tmp/gtkdialog-page-setup.ini</output>
  <action signal="response" function="save">PAGE_SETUP</action>
  <action signal="response">exit:response</action>
</pagesetupdialog>

See examples/pagesetupdialog/pagesetupdialog for a complete runnable example. This widget was introduced in gtkdialog version 0.9.1.
