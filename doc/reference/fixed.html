fixed widget

A GTK+ 2 GtkFixed container. It places each direct child at explicit pixel coordinates.

Definition 

<fixed tag_attr="value"...>
	widget x="horizontal-position" y="vertical-position"...
	<variable>varname</variable>
	<sensitive>state</sensitive>
	<action signal="type">activity</action>...
</fixed>

At least one direct child is required by the XML grammar. Every child defaults to position 0, 0; its x and y attributes are signed decimal pixel coordinates relative to the upper-left corner of the fixed container.

Tag Attributes

Writable GTK+ 2 GtkFixed, GtkContainer and GtkWidget scalar properties can be used on the container. The following attributes belong to each direct child instead:

NameDescriptionDefaultSince
xHorizontal position in pixels0 0.9.0
yVertical position in pixels0 0.9.0

Normal child attributes such as width-request, height-request, visible, space-expand and space-fill retain their existing meanings.

Directives, Signals and Functions

The optional variable directive names the container for common functions and exports an empty value. The widget has no default signal and no type-specific input, output, refresh, save, clear or movement functions.

Common Contract

Common directives, GtkWidget signals, state and general functions, and action conditions are documented in the common widget contract. The show, hide, enable, disable and grabfocus functions apply to the whole container.

Example 

<fixed width-request="400" height-request="180">
	<text x="16" y="18"><label>Name</label></text>
	<entry x="92" y="12" width-request="210">
		<variable>NAME</variable>
	</entry>
	<button x="250" y="120"><label>Continue</label></button>
	<variable>FIXED_AREA</variable>
</fixed>

Notes

Absolute positioning does not adapt automatically to translated text, font changes, themes or resizable windows. Prefer grid, boxes, alignment and size groups for normal forms; use fixed for layouts whose pixel coordinates are intentionally part of the interface.

This widget was introduced in version 0.9.0.
