comboboxentry widget

Shared directives, GtkWidget signals, state and general functions, and action conditions are summarized in the common widget contract. The sections below document this tag's specific surface.

A GtkComboBoxEntry. The established text-only model remains the default. An opt-in flat rich model adds icons, markup and item styling while retaining the editable entry. Optional completion filters the same flat model while text is typed.

Definition 

<comboboxentry tag_attr="value"...>
	<default>text</default>
	<variable>varname</variable>
	<input>command</input>...
	<input file>filename</input>...
	<sensitive>state</sensitive>
	<action>activity</action>...
	<action signal="type">activity</action>...
	<action function="type">parameter</action>...
	<item>data</item>...
	<output file>filename</output>
</comboboxentry>

"..." denotes acceptance of multiples of the same thing.

With item-model="rich", selecting a list item displays its plain label in the editable entry and exports its optional stable value. Typing or supplying an unmatched <default> clears the list selection and exports the entry text instead. Icons and styles apply to the drop-down list; Pango markup is stripped for the editable field. The model is intentionally flat. The hierarchical rich-tree model belongs to comboboxtext.

With completion="true", the completion popup and the drop-down list share one flat model, including data reloaded by refresh. Rich completion rows retain their icons, markup, sensitivity, colours and fonts. Choosing a completion row makes it the active combobox item, so its stable value is exported; freely typed text continues to be exported unchanged.

The matching controls are shared with entry and tree: the default remains case-insensitive prefix matching, while completion-match="contains" finds a fragment anywhere in the visible item text and completion-case-sensitive="true" makes letter case significant. Rich items are matched by their plain editable text rather than markup or stable value.

Signals

The default signal is "changed", emitted when the active item is changed and when typing into the entry.

The "activate" signal is emitted when the user activates the entry with the Enter key.

The "file-changed" signal is emitted if file-monitor is true and the input file being monitored has changed.

The following signals are connected-up for all widgets:

button-press-event, button-release-event, configure-event, enter-notify-event, leave-notify-event, focus-in-event, focus-out-event, hide, show, realize, key-press-event, key-release-event, map-event, unmap-event

Notes

1. The save function will write the entry text to the output file if it is unique and non-null.

This widget was introduced in version 0.7.21. Rich items were added in version 0.9.2.

Example 

<comboboxentry item-model="rich" icon-size="20"
	completion="true" completion-minimum-key-length="1"
	completion-match="contains">
	<variable>COMMAND</variable>
	<default>open</default>
	<item value="open" stock="gtk-open">Open document</item>
	<item value="save" stock="gtk-save" foreground="#204a87">Save document</item>
</comboboxentry>

See examples/comboboxentry/comboboxentry_rich for a runnable example.
