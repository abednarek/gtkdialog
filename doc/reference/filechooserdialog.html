filechooserdialog

A top-level GTK+ 2 GtkFileChooserDialog for opening or saving files and selecting or creating folders.

Definition 

<filechooserdialog tag_attr="value"...>
	<default>selection</default>
	<variable>response variable</variable>
	<input>selection command</input>
	<input file>selection filename</input>
	<input response="true">response command</input>
	<input file response="true">response filename</input>
	<sensitive>state</sensitive>
	<action signal="response">activity</action>...
	<output file>selection filename</output>
	<output file response="true">response filename</output>
	<output file current-folder="true">folder filename</output>
</filechooserdialog>

This element replaces the normal top-level window. It cannot be nested or contain child widgets. The existing embedded chooser, compact filechooserbutton and fileselect action keep their established behaviour.

Writable GtkFileChooser and GtkWindow properties are also accepted. Useful examples include select-multiple, local-only, show-hidden, do-overwrite-confirmation, create-folders, title and modal. Explicit chooser attributes are applied before the initial selection.

Value, Input and Signals

The widget variable contains the last named dialog response, normally accept or cancel. The variable is updated before actions connected to the default response signal run. A response does not implicitly close the dialog: use exit for a root program or closewindow for a launched dialog.

Normal command and file inputs select filenames or URIs. Multiple values are separated by newlines and require select-multiple="true". As required by GTK+ 2, entries in one multiple selection must have the same parent folder; entries from other folders are reported and ignored. An input carrying response="true" instead supplies a named or numeric dialog response. Its first initialization stores the response without emitting it; a later refresh emits it and runs the normal response actions. Input files support the common monitor and automatic-refresh attributes.

Explicit chooser signals include file-activated, selection-changed, update-preview and current-folder-changed. The default action signal remains response, as for other top-level dialogs.

Saving, Clearing and Lifecycle

save writes the current selection to every normal output file. Multiple selections are newline-separated without a trailing newline. response="true" selects response output, while current-folder="true" selects current-folder output; combining both selectors on one output is rejected. Folder output follows selection-format.

clear removes the selection and stored response. In save and create-folder modes it also clears the suggested name. removeselected removes only the current selection. The fileselect function replaces the selection using the configured format.

GTK owns filters, buttons and chooser internals after construction. Gtkdialog frees temporary filename/URI lists and strings returned by the chooser exactly once. Closing a launched dialog releases its actions, input monitors and GTK objects through the normal top-level lifecycle, while the source environment variable is retained for a later relaunch.

Common Contract

Common directives, GtkWidget signals, state and general functions, and action conditions are documented in the common widget contract. The sections above describe facilities specific to this tag.

Example 

<filechooserdialog title="Choose source files" action="open"
    current-folder="/tmp" select-multiple="true"
    filter-name="C source" filter-pattern="*.c;*.h">
  <variable>FILE_DIALOG_RESPONSE</variable>
  <output file>/tmp/gtkdialog-selected-files</output>
  <action signal="response" function="save">FILE_DIALOG_RESPONSE</action>
  <action signal="response">exit:response</action>
</filechooserdialog>

See examples/filechooserdialog/filechooserdialog for a runnable example. This widget was introduced in gtkdialog version 0.9.1.
