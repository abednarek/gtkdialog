tree widget

Shared directives, GtkWidget signals, state and general functions, and action conditions are summarized in the common widget contract. The sections below document this tag's specific surface.

A GtkTreeView packed inside a GtkScrolledWindow

Definition 

<tree tag_attr="value"...>
	<label>text</label>
	<variable>varname</variable>
	<height>value</height>
	<width>value</width>
	<input>command</input>...
	<input icon-column="index">command</input>...
	<input stock-column="index">command</input>...
	<input format="json">command</input>...
	<input file>filename</input>...
	<input file icon-column="index">filename</input>...
	<input file stock-column="index">filename</input>...
	<input file format="json">filename</input>...
	<sensitive>state</sensitive>
	<action>activity</action>...
	<action signal="type">activity</action>...
	<action function="type">parameter</action>...
	<item>data</item>...
	<item combo-column="index">choice</item>...
	<item icon-name="image">data</item>...
	<item stock-id="gtk-image">data</item>...
	<output file>filename</output>
	<output file format="json">filename</output>
</tree>

"..." denotes acceptance of multiples of the same thing.

Hierarchical JSON Format

The legacy pipe-separated input and output formats remain the default. JSON is selected only by adding format="json" to an input or output directive. Configure with --with-json-glib to enable this support. The optional feature is listed as JSON-GLib by gtkdialog --version when enabled.

A JSON document is a versioned object containing a rows array. Each row requires a positional values array matching the columns declared by the XML label. Missing trailing values use the model defaults; supplying more values than declared columns rejects the entire document. Values may be strings, numbers, Booleans or null. Use a decimal string for a uint64 value that may exceed the signed JSON integer range. Numeric columns accept only values that can be converted completely, without overflow, to their declared column-type; otherwise the complete JSON document is rejected before any row is inserted. This stricter rule applies only to JSON input. The legacy pipe-separated input keeps its historical conversion to zero.

{
  "version": 1,
  "rows": [
    {
      "icon-name": "folder",
      "values": ["Projects", 2, true],
      "expanded": true,
      "children": [
        {
          "stock-id": "gtk-file",
          "values": ["README", 1, false]
        }
      ]
    }
  ]
}

The optional icon-name and stock-id members select the row icon and are mutually exclusive. If neither is present, the tree's default icon is used. The optional Boolean expanded member controls the initial expansion state, and the optional children array uses the same row format recursively. Nesting is limited to 256 levels. JSON input is completely validated before any row from that document is inserted.

An optional style object applies presentation defaults to every cell in its row. An optional cells array contains a style object or null for each data column; cell properties override the row style, which in turn overrides the corresponding column-* setting. The following properties are accepted: background, foreground, font, weight, style, underline, strikethrough, xalign, yalign, xpad, ypad, ellipsize, wrap-mode, wrap-width, text-align, icon-name, stock-id, pixbuf-file and pixbuf-size. The three image source properties are mutually exclusive. Text-only properties are ignored by non-text renderers. GTK theme colours remain in control while a row is selected so that focus and selection stay readable.

{
  "values": ["Build", 73, true],
  "style": {"background": "#f5f5f5"},
  "cells": [
    {"foreground": "#204a87", "weight": "bold"},
    {"xalign": 1.0},
    null
  ]
}

JSON output preserves the row hierarchy, values, icons, styles and current expansion state. These optional members remain part of version 1: older builds that do not recognise them still load the row values and hierarchy. A legacy <output file> continues to use its historical flat format and behavior.

Signals

The default signal is "row-activated", emitted when the user double-clicks a row and also when a row is selected and one of the keys Space, Shift+Space, Return or Enter is pressed.

The "changed" signal is emitted when the selection has changed (please see link about this).

The "cursor-changed" signal is emitted when the position of the cursor (focused cell) has changed.

The "cell-edited" signal is emitted after an in-place text or combo edit has updated the model. It is available only for columns enabled by column-editable; the tree variable reflects the edited selection when actions run.

A combo renderer presents choices declared by <item combo-column="index">. Choice items belong to the renderer model and are not inserted as tree rows. Unless the corresponding column-combo-has-entry value is true, only declared choices can be selected.

A spin renderer presents a native spin button while editing. Its range, increment and decimal places are configured by the corresponding column-spin-min, column-spin-max, column-spin-step and column-spin-digits values.

An accel renderer displays and edits XML-safe GTK+ accelerator names such as Primary+O or Primary+Shift+O in a string column. Capturing a key combination updates the model and emits accel-edited. Pressing Backspace clears the value and emits accel-cleared.

The "cell-toggled" signal is emitted after an activatable toggle or radio renderer has updated the model. String columns store true or false; numeric columns store 1 or 0. An editable radio renderer permits one active value among rows with the same parent; activating a row clears that column in its siblings. Clicking the already active row leaves it active.

A progress renderer presents its column value as a native progress bar. Values are rounded to the nearest integer and limited to the display range from 0 to 100; the underlying model and exported value are not changed.

A pixbuf renderer interprets the model value as an icon name, stock ID or filename according to column-pixbuf-source. An icon-text renderer keeps the model value as text and places an image before it. The first icon-text column also honours the existing row icon-name and stock-id metadata. Loaded images are cached within the current model generation. The clear and refresh functions discard both successful and failed cached loads, allowing changed or newly created files to be read.

A markup renderer treats a string column as explicit Pango markup. The stored and exported value remains the original markup string; plain text remains the default renderer, so existing data is never interpreted as markup unless this renderer is requested.

A color renderer treats a string column as a GTK+ colour specification and displays a solid swatch. The original text remains in the model and output. Swatches are cached within the current model generation and discarded by clear or refresh; an invalid colour produces a warning and an empty cell.

The "file-changed" signal is emitted if file-monitor is true and the input file being monitored has changed.

The following signals are connected-up for all widgets:

button-press-event, button-release-event, configure-event, enter-notify-event, leave-notify-event, focus-in-event, focus-out-event, hide, show, realize, key-press-event, key-release-event, map-event, unmap-event

Notes

When context-menu is set, right-clicking a row selects it before the popup actions run. In multiple-selection mode, right-clicking an already selected row preserves the complete selection; right-clicking another row replaces it. Right-clicking empty space and keyboard invocation preserve the current selection. See the popupmenu reference for the menu definition.

With multiple selection, the widget variable contains the selected values in row order, separated by newline characters.

The removeselected function removes every selected row when multiple selection is enabled.

1. This widget has a default dimension of 200x100 which can be overridden with the height and/or width directives.

2. When saving, due to the multiple input data formats, the columns are output in the following raw state: icon-name | stock-id | data0 | data1 | ...
