drawingarea widget

A GTK+ 2 GtkDrawingArea that presents an owned raster image and receives normal pointer actions. Opt-in modes use GooCanvas 1 for interactive object scenes or GtkDatabox 0.9 for numeric plots without changing the established raster mode.

Definition 

<drawingarea tag_attr="value"...>
	<width>canvas width</width>
	<height>canvas height</height>
	<default>initial image filename</default>
	<variable>varname</variable>
	<input>command returning a filename</input>
	<input file>image filename</input>
	<sensitive>state</sensitive>
	<action signal="type">activity</action>...
	<output file>image filename</output>
</drawingarea>

Custom Attributes

NameDescriptionValue
scale-modeHow the image occupies the canvasnone, fit or stretch
interpolationFilter used while scalingnearest, tiles, bilinear or hyper
backgroundCanvas backgroundGTK colour specification

scale-mode defaults to none and interpolation defaults to bilinear. In fit mode the aspect ratio is preserved and the image is centred; stretch fills both dimensions. Without width and height directives, the successfully loaded image supplies its natural dimension. A blank canvas falls back to 320 by 180 pixels.

Optional GooCanvas object-scene mode

Set goocanvas="true" to create a GooCanvas 1 GTK2 scene. This mode requires --with-goocanvas and --with-json-glib at configure time. Builds without both create a blank placeholder and report the unavailable feature. The attribute is opt-in, so raster drawing areas and GtkDatabox plots retain their existing behaviour.

NameDescriptionValue
goocanvasEnable object-scene modetrue or false
canvas-left, canvas-top, canvas-right, canvas-bottomScrollable scene boundsFinite numbers; default 0, 0, 640, 400
scaleInitial scene magnification0.1 to 16; default 1

A file or command input is a complete document of the form {"version":1,"items":[...]}. Each <item> is one JSON item object; inline items are followed by input documents in directive order. Supported types are group with recursive children, rect, ellipse, text, image, path and polyline. Type geometry uses the corresponding names: rectangles use x, y, width, height; ellipses use center-x, center-y, radius-x, radius-y; text uses text, x, y, width, anchor; images use file, x, y; paths use SVG-compatible data; and polylines use a flat numeric points array plus optional closed.

All types accept an optional unique id, fill-color, stroke-color, line-width, opacity, visible, tooltip, translate-x, translate-y, scale and rotation. Text also accepts a Pango font. An item with an ID can emit item-activated; set draggable to true to move it with button 1 and emit item-moved. The drawing-area variable contains the last activated item ID. Drag translations are written back to the owned JSON document, so save persists them.

refresh validates and builds a complete replacement tree before displaying it. A malformed document, invalid item or failed image load leaves the previous scene intact. clear releases the scene tree and JSON, while save writes versioned JSON to the first output file. The existing zoomin, zoomout and zoomreset functions change whole-scene magnification.

Optional GtkDatabox plot mode

Set databox="true" to create a GtkDatabox 0.9 GTK2 plot. This mode is available when gtkdialog was configured with --with-gtkdatabox. A build without that package creates a blank placeholder and reports the missing optional feature; ordinary drawing areas are unaffected.

Native GtkDatabox properties are also tag attributes. The most useful are enable-selection, enable-zoom, scale-type-x, scale-type-y and box-shadow. Series option lists repeat cyclically if they contain fewer entries than the number of Y columns. Logarithmic axes require positive explicit limits. Automatic limits ignore non-positive values on a logarithmic axis and apply the requested margin in logarithmic rather than linear space.

Each non-empty <item>, file-input line or command-output line has the format x|y1|y2|.... All rows in one refresh must have the same number of columns. Item rows are loaded first, followed by input sources in document order. Blank lines and lines beginning with # are ignored. Invalid or unavailable input leaves the previous valid plot intact. The save function writes the accepted table to the first output file, while clear releases every series and its data.

Dragging with the left mouse button creates a selection. The variable is empty until then and contains x1|y1|x2|y2 afterwards. The default action signal is selection-finalized; explicit selection-started, selection-changed, selection-canceled and zoomed actions are supported. The existing zoomin, zoomout and zoomreset functions respectively zoom to the current selection, step out and restore the complete limits.

Value and functions

A file input names an image to load. A command input reads an image filename from its first output line. Several inputs are evaluated in order and the last successfully loaded image wins. The variable contains the original filename, not an internally resolved search path.

refresh reloads the default and input sources, clear removes the current image, and save writes the original unscaled raster to the output filename. The filename extension chooses the output format. A failed load leaves the previous valid image intact.

Signals

The type-specific expose-event action runs after the current raster is drawn. There is no default signal. Normal button-press-event and button-release-event actions receive PTR_X, PTR_Y, PTR_BTN, PTR_MOD and the existing root-coordinate environment values.

Ownership

The drawing area owns one source pixbuf and at most one cached scaled pixbuf. Replacing or clearing the image releases both previous objects, and destroying the widget releases the remaining image data and source filename.

In object-scene mode GooCanvas owns the displayed item hierarchy. The drawing area separately owns one matching JSON document and the selected ID; each interactive item owns only its event metadata. Replacement first releases the old item tree and its metadata, then the old JSON document. Destruction and clear follow the same order.

In plot mode gtkdialog owns every numeric array and every graph reference, because GtkDatabox borrows both. Refresh first detaches the previous graphs, then releases their objects and arrays. Widget destruction performs the same ordered cleanup.

Common Contract

Common directives, GtkWidget signals, state and general functions, and action conditions are documented in the common widget contract. The sections above describe the facilities specific to this tag.

Example 

<drawingarea scale-mode="fit" background="#20242a">
	<width>480</width>
	<height>270</height>
	<input file>/tmp/preview.png</input>
	<output file>/tmp/saved-preview.png</output>
	<variable>PREVIEW_IMAGE</variable>
	<action signal="button-press-event">
		echo "$PTR_X,$PTR_Y button $PTR_BTN"
	</action>
</drawingarea>

<drawingarea goocanvas="true" canvas-right="480" canvas-bottom="260">
  <item>{"type":"rect","id":"card","x":30,"y":30,
    "width":150,"height":80,"fill-color":"#f5c211",
    "stroke-color":"#865e00","draggable":true}</item>
  <item>{"type":"text","id":"caption","text":"Drag the card",
    "x":105,"y":70,"anchor":"center","font":"Sans Bold 12"}</item>
  <variable>SCENE_ITEM</variable>
  <action>echo "Activated $SCENE_ITEM"</action>
  <action signal="item-moved">echo "Moved $SCENE_ITEM"</action>
  <output file format="json">/tmp/scene.json</output>
</drawingarea>

<drawingarea databox="true" series-types="lines|points"
  series-colors="#3584e4|#e66100" series-sizes="2|5">
  <width>480</width>
  <height>260</height>
  <item>0|0|2</item>
  <item>1|1|1</item>
  <item>2|0|3</item>
  <variable>PLOT_SELECTION</variable>
  <action>echo "Selected $PLOT_SELECTION"</action>
</drawingarea>

This widget was introduced in gtkdialog version 0.9.0.
